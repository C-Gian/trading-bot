## Closed-bar signal semantics

Initial research semantics:

- canonical market path: 1m;
- strategy signal clock: 1h;
- regime/context clock: 4h;
- only completed bars may be used;
- a signal is decided only after the relevant 1h bar has fully closed;
- 4h context is as-of the most recently fully closed 4h bar available at signal time;
- entry occurs at the next canonical 1m bar open after the signal bar closes;
- this is also the next 1h bar open for normal UTC-aligned data;

The engine must carry explicit signal timestamps and execution timestamps and reject
impossible temporal ordering.

# Stage D — execution/fill rules

Version every material assumption.

Implement a deterministic long-only event-driven simulator that resolves market path
with canonical 1m bars.

Document and test all cases.

## Entry

Base execution:

- signal after completed 1h bar;
- enter at next available eligible 1m open;
- apply configured adverse entry execution friction;
- if the required next-bar execution is not observable because of a data gap, do not
  silently jump forward and pretend the order filled normally.

Use an explicit non-tradable/data-invalid outcome.

## Stop

For a long:

- if a 1m bar opens below the stop, fill at the adverse opening price rather than
  granting the stale stop price;
- if the bar trades through the stop intrabar without an opening gap, use the stop
  trigger/fill rule plus configured adverse exit friction.

## Target

For a long target:

- if target is reached intrabar, use the documented target fill convention;
- do not grant impossible favorable slippage;
- if a bar opens beyond a target, use a conservative deterministic target convention
  documented in the contract.

## Ambiguous TP/SL bar

If both stop and target are reachable within the same 1m OHLC bar and ordering cannot
be known:

`STOP_FIRST_V1`

This is intentionally conservative.

Do not infer intrabar ordering from OHLC.

## Expiry

Define exactly which canonical bar closes a position at the maximum holding horizon.

Use a deterministic market-exit convention with configured adverse friction.

## End-of-data

A position that cannot be resolved because the dataset ends must never be silently
counted as a win/loss.

Return an explicit unresolved/end-of-data terminal state.

## Data gaps

If an unobserved canonical interval makes barrier ordering/execution unknowable, return
an explicit data-quality-invalid/unresolved outcome according to the contract.

Do not forward-fill the missing path.

Future experiment preregistrations must declare how invalid/unresolved trades enter the
primary metric denominator.

The engine must always report their count separately.
